# 内容润色原则

将收集到的原始数据进行润色扩展，核心方法：

```
用户原始回答 ──→ 补充背景/方法/结果/影响/下一步 ──→ 填入模板
```

## 扩展纬度

每条内容从以下纬度展开，不得直接填入用户原话：

| 原始回答 | 润色方向 | 示例 |
|---------|----------|------|
| "测试惊喜红包券" | 补充：测试范围、用例数量、已完成/进行中、发现的问题 | "覆盖了红包领取→发放核心链路（12/12 通过），异常场景完成 65%，发现 2 个 Bug" |
| "遇到环境问题" | 补充：根因分析、影响范围、已采取措施、预期修复时间 | "预发布环境 OAuth 配置未初始化导致 3 个用例阻塞，已联系运维，预期明天修复" |
| "学了 Bug 场景" | 补充：具体学了什么场景、为什么重要、怎么应用 | "并发领取时的金额扣减一致性场景，加深了对分布式事务的理解，可沉淀为测试 CheckList" |
| "明天继续测试" | 补充：任务分解、依赖条件、交付物 | "完成异常场景收尾 → 跟进环境修复 → 输出测试报告初稿" |

## 分类润色要求

| 类别 | 润色要求 |
|------|----------|
| **工作进展** | 补充范围、具体事项、已完成/进行中、发现的问题数 |
| **问题** | 补充根因分析、影响评估、已采取措施、预期修复时间 |
| **心得** | 补充具体场景、为什么重要、如何应用到后续工作 |
| **计划** | 补充任务分解（主任务 → 子步骤）、依赖条件、交付物 |
